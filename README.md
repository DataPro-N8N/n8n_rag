# RAG Document Q&A with n8n + Ollama

This n8n workflow combines document upload, PDF extraction, text
chunking, Ollama embeddings, in-memory vector storage, retrieval, and an
Ollama chat model into one RAG (Retrieval-Augmented Generation)
workflow.

## Architecture

``` text
                    DOCUMENT INGESTION
Form Upload
    |
    v
Extract from File (PDF)
    |
    v
Simple Vector Store (Insert)
    ^
    |
Default Data Loader
    ^
    |
Recursive Character Text Splitter
    ^
    |
nomic-embed-text
    |
    +-------------------------------+

                    QUESTION / ANSWER

When Chat Message Received
    |
    v
Question and Answer Chain
    |                 ^
    |                 |
    |            Ollama Chat Model
    |
    v
Vector Store Retriever
    |
    v
Simple Vector Store (Retrieve)
    ^
    |
Embeddings Ollama
(nomic-embed-text)
```

## Prerequisites

Install and run Ollama on Windows.

Check Ollama:

``` powershell
ollama --version
```

Start the Ollama server:

``` powershell
ollama serve
```

Verify the server:

``` text
http://127.0.0.1:11434
```

Check installed models:

``` powershell
ollama list
```

The workflow needs:

-   `nomic-embed-text` for embeddings
-   A chat model such as `llama3.2` for generating answers

Install the models if required:

``` powershell
ollama pull nomic-embed-text
ollama pull llama3.2
```

## n8n Ollama Credential

In n8n, open the Ollama credential used by both Ollama nodes.

Use:

``` text
Base URL: http://127.0.0.1:11434
```

Do not enter:

``` text
http://127.0.0.1:11434/api
http://127.0.0.1:11434/api/chat
```

The Ollama client adds the API path automatically.

## Workflow 1: Document Upload

The upload branch performs:

1.  `On form submission`
2.  `Extract from File`
3.  `Simple Vector Store` in `insert` mode
4.  `Default Data Loader`
5.  `Recursive Character Text Splitter`
6.  `Embeddings Ollama`

The shared vector-store key is:

``` text
vector_store_key
```

The same key is used by the retrieval branch.

### Document Loader

The Default Data Loader uses the extracted `text` field.

### Text Splitter

The Recursive Character Text Splitter is used to divide the document
into smaller chunks.

The current workflow specifies:

``` text
Chunk overlap: 200
```

## Workflow 2: Ask Questions

The chat branch performs:

1.  `When chat message received`
2.  `Question and Answer Chain1`
3.  `Vector Store Retriever1`
4.  `Simple Vector Store2`
5.  `Embeddings Ollama1`
6.  `Ollama Chat Model`

The retrieval vector store uses:

``` text
Memory Key: vector_store_key
```

The embedding model is:

``` text
nomic-embed-text:latest
```

The chat model is:

``` text
llama3.2:latest
```

## How the RAG Flow Works

Suppose the user uploads:

``` text
project.pdf
```

The workflow extracts the PDF text, splits it into chunks, converts each
chunk into an embedding, and stores those embeddings in the Simple
Vector Store.

When the user asks:

``` text
What are the functional requirements?
```

the question is converted into an embedding using `nomic-embed-text`.

The retriever searches the stored document chunks and returns relevant
information.

The Question and Answer Chain passes the question and retrieved context
to the Ollama chat model.

The chat model generates the final answer.

## Test Procedure

### 1. Start Ollama

``` powershell
ollama serve
```

Keep this terminal running.

### 2. Verify models

``` powershell
ollama list
```

Expected models should include something similar to:

``` text
llama3.2:latest
nomic-embed-text:latest
```

### 3. Upload a PDF

Open the form generated by `On form submission` and upload a PDF.

Wait until the upload workflow completes successfully.

### 4. Open the chat

Use the `When chat message received` interface.

Ask:

``` text
What is this document about?
```

Then try:

``` text
What are the functional requirements?
```

or:

``` text
Summarize the document.
```

## Important: Simple Vector Store

The workflow currently uses `Simple Vector Store`.

This is useful for local development and learning, but it is an
in-memory vector store. For a production application, use a persistent
vector database such as:

-   Supabase with pgvector
-   PostgreSQL/PGVector
-   Qdrant
-   Pinecone
-   Weaviate

## Troubleshooting

### Error: `connect ECONNREFUSED ::1:11434`

This normally means n8n cannot connect to Ollama.

Start Ollama:

``` powershell
ollama serve
```

Use this n8n credential URL:

``` text
http://127.0.0.1:11434
```

Using `127.0.0.1` instead of `localhost` can avoid IPv6 `::1` connection
issues.

### Error: `fetch failed`

Check that Ollama is running:

``` powershell
curl.exe http://127.0.0.1:11434/api/tags
```

If Ollama is working, it should return model information.

### Error: `Method Not Allowed`

Check the Ollama credential.

Correct:

``` text
http://127.0.0.1:11434
```

Incorrect:

``` text
http://127.0.0.1:11434/api
```

Incorrect:

``` text
http://127.0.0.1:11434/api/chat
```

Also verify that the Ollama Chat Model uses a chat model such as:

``` text
llama3.2:latest
```

Do not use `nomic-embed-text` as the chat model.

### Error: `A Text Splitter sub-node must be connected and enabled`

Connect:

``` text
Recursive Character Text Splitter
        |
        v
Default Data Loader
        |
        v
Simple Vector Store
```

The Data Loader must have its Text Splitter sub-node connected.

### Error: `A Document sub-node must be connected and enabled`

Connect:

``` text
Default Data Loader
        |
        v
Simple Vector Store
```

The Data Loader must provide the document input to the vector store.

### Error: `A Embedding sub-node must be connected and enabled`

Connect:

``` text
Embeddings Ollama
        |
        v
Simple Vector Store
```

Make sure the embedding model is installed:

``` powershell
ollama list
```

## Recommended Node Configuration

  Node                        Configuration
  --------------------------- -------------------------------------
  Form Trigger                Upload Document
  Extract from File           PDF
  Simple Vector Store         Insert
  Embeddings Ollama           `nomic-embed-text`
  Data Loader                 JSON data: `text`
  Text Splitter               Recursive Character Text Splitter
  Chat Trigger                When chat message received
  Question and Answer Chain   Retrieval QA
  Vector Store Retriever      Connected to retrieval vector store
  Simple Vector Store 2       Retrieve / Vector Store for Chain
  Embeddings Ollama 1         `nomic-embed-text:latest`
  Ollama Chat Model           `llama3.2:latest`

## Final Goal

The complete application should behave like this:

``` text
Upload PDF
   |
   v
Extract + Chunk + Embed
   |
   v
Vector Store
   |
   |
   +----------------------+
                          |
User asks a question      |
   |                      |
   v                      |
Embed question            |
   |                      |
   v                      |
Retrieve relevant chunks  |
   |                      |
   v                      |
Ollama Chat Model <-------+
   |
   v
Answer based on the PDF
```

## Notes

-   Keep `ollama serve` running while testing locally.
-   Use the same vector-store memory key: `vector_store_key`.
-   Use `nomic-embed-text` for embeddings.
-   Use a separate chat model such as `llama3.2` for answers.

    database.
